# Optional reference-lab conditions

These local fixtures implement candidates for [TACP-0.4](../VALIDATION-REFERENCE-PROTOCOL.md). Each task asks the browser observer to identify the reading room’s opening hours (9 a.m. to 5 p.m.), then follow **Read the visitor information** and recognize that the room is on the ground floor. The start and completion pages use the same condition. The [operator handoff](OPERATIONS.md) governs service limits, private administration, teardown, and any separately authorized deployment.

| Candidate and rule version | Start and completion | Configured response |
|---|---|---|
| REF-CLIENT v1 | `/client`, `/client/complete` | 200 for a parsed `Sec-Fetch-Mode` value exactly equal to `navigate`, otherwise 403 |
| REF-TOR-DIFF v1 | `/tor-diff`, `/tor-diff/complete` | 403 for a listed peer, 200 for an unlisted peer in a supported address family, and 503 when that family is unavailable |

Both conditions are opt-in. The baseline prefix has neither set of routes. They use fixed HTML, a single same-origin link, and the baseline server’s request limits and logging settings. The responses use no external resources, redirects, cookies, or request-specific content.

## REF-CLIENT qualification

The W3C Fetch Metadata draft describes `Sec-Fetch-Mode: navigate` for navigation, including a user clicking a same-origin link. The lab uses case-sensitive equality on nginx’s parsed field value. A missing value, a different mode, or a malformed or repeated value fails the gate. The header is a synthetic discriminator that an HTTP client can supply. The unchanged scanner’s probe sends User-Agent, Accept, and Accept-Language. Its optional SOCKS routing leaves the HTTP header profile the same on Tor and direct requests. [Fetch Metadata §2.2](https://www.w3.org/TR/2026/WD-fetch-metadata-20260921/#sec-fetch-mode-header) · [Scanner probe](../check_tor.zsh)

The preparation Mac’s installed application metadata on 2026-11-14 identified Tor Browser 16.0.1 (build 15326.11.9) and Firefox 159.0.1 (build 15926.11.2). These are candidate profiles from app metadata. No browser was launched or request observed. Recheck the actual qualification host and freeze the exact browser versions and builds, OS, Tor Browser security level, browser state, scanner commit and curl version, nginx package and effective configuration, and trusted HTTPS origin and task URLs in the readiness record. A permitted ordinary-browser alternative must be qualified by its own exact version/build. Independently verify the single parsed header value for both the address-bar load and the approved link navigation in **each** browser, plus its absence from the unchanged scanner over Tor and direct. Corroborate the expected HTTP status on both task routes and confirm that each browser can complete the task. The W3C draft and synthetic requests establish the intended rule. Those sources leave actual browser behavior, deployment, and Tor-path compatibility for later qualification.

For separately authorized eligibility checks, use a scoped, transient diagnostic that records only approved field presence and equality, method if needed, route ID, and status. For browsers, a local inspection of the two already-authorized document requests can verify the field on the client. The origin must also be independently checked for the expected rule behavior. Disable temporary diagnostics before collection. Avoid full request export, header dumps and third-party echo services. Defer if the header is absent, changed or inconsistent in either approved browser or at the origin, or if the independent evidence or its required authority is unavailable. Requalify after any browser, scanner, nginx, or delivery-path change that can affect this condition.

## REF-TOR-DIFF source and freeze

Use a single timestamped Tor Project CollecTor `tordnsel 1.0` file from its recent exit-list directory. The source publishes exit addresses observed by active tests, including cases where the address used to exit differs from a relay’s advertised address. The Tor Project documents that the exit scanner lacks IPv6 support and can carry earlier observations forward for up to 48 hours. For this candidate, enable IPv4 only in any future qualified deployment. Defer IPv6 and omit the IPv6 listener and AAAA record. A generated file deliberately returns the unavailable response on an IPv6 listener if one is present. [CollecTor format](https://metrics.torproject.org/collector.html#type-tordnsel) · [Tor Project exit scanner operations](https://rhatto.pages.torproject.net/wikipelago/network-health/metrics/exit-list-check/#major-caveats)

The compiler uses the original UTC filename and the reviewed Base64-encoded `sha256` field from the independently retrieved CollecTor index. The digest identifies the cached bytes and detects differences from the reviewed file. Source authority comes from the authenticated transfer and operator review. Record the source URL, acquisition time UTC, source timestamp, source digest, effective include digest, rule and deployment versions, included count and observation time bounds, supported family, and approved batch deadline. The compiler accepts a bounded, annotated, local file with at most 2 MiB and 8,192 unique public IPv4 addresses. It validates record structure, timestamps, address syntax and the digest, keeps the latest observation for each address, and generates exact single-address entries. Any compiled membership must still be under 24 hours old at the frozen deadline. The file and its newest observation must both be under three hours old at that deadline. These are lab qualification thresholds, informed by the upstream hourly cycle and three-hour publication monitoring. If the usable set is empty, the input is missing or invalid, or the window exceeds the thresholds, compilation fails and the route remains unavailable for selection. A successful compilation still requires review of completeness and plausibility. [CollecTor index format](https://metrics.torproject.org/collector.html#automated-downloads) · [Tor Project monitoring](https://rhatto.pages.torproject.net/wikipelago/network-health/metrics/exit-list-check/#monitoring)

nginx evaluates the peer address directly from the connection using `geo $remote_addr`. Use direct ingress with a source-preserving network path, and verify the effective config contains no `real_ip_header`, `set_real_ip_from`, PROXY protocol listener, or `geo proxy` setting that can substitute a different address. Forwarding headers supplied by clients have no role. Any proxy or source-rewriting ingress requires a different reviewed design and fresh qualification. [nginx geo directive](https://nginx.org/en/docs/http/ngx_http_geo_module.html)

A listed source may have changed since it was observed, may share an address with unrelated traffic, and may encounter different exit policies at this origin. An unlisted source may be a Tor exit absent from the age-filtered snapshot. Assess the observed automated Tor and clearnet control separately from the two browser outcomes. Different Tor clients and retries can use different exits. A membership branch gives no same-exit evidence.

## Stage and verify

Start with a **fresh private configuration directory** from the [operator handoff](OPERATIONS.md). Use Python 3.9 or newer for the offline compiler and a security-maintained nginx version whose header normalization passes the local fixtures. For either condition, place `condition-task-start.inc` and `condition-task-complete.inc` beside `nginx.conf`. Then stage only the required files.

- **REF-CLIENT** requires `condition-http-client.conf` and `condition-routes-client.conf`.
- **REF-TOR-DIFF** requires `condition-tor-diff-gate.inc`, `condition-routes-tor-diff.conf`, and the generated `condition-http-tor-diff.conf`. Run the compiler before staging the route file. The compiler makes no network requests and refuses to overwrite an existing include.

```sh
python3 reference-lab/freeze_exit_snapshot.py "$cached_file" \
  --sha256 "$reviewed_sha256" --batch-end "$deadline_utc" --prefix "$lab"
```

Pass the exact Base64 index value as `reviewed_sha256`. Here `cached_file` preserves the CollecTor filename `YYYY-MM-DD-HH-MM-SS`, `deadline_utc` has form `YYYY-MM-DDTHH:MM:SSZ`, and `lab` is the private directory containing `nginx.conf`. The include starts with the source provenance and cutoff. Restrict the complete loaded configuration to the approved operator and service account. Check it with `nginx -t` and exact-route probes. Review the include digest privately. The wildcard includes use only files staged beside `nginx.conf`. A Tor route configuration without its generated membership variable fails config validation.

**The frozen deadline is a hard readiness and run gate.** The nginx process loads the snapshot at start/reload and applies it until stopped. It has no runtime snapshot refresh or clock-expiry check. Verify current UTC, the expected digest, and the declared deadline before start, before any permitted restart or reload, and before each case. Leave time for the full paired window and ingress closure. Close access by the frozen deadline, or earlier if validity, review, or authority is lost. Never restart or reload an expired snapshot. If the service cannot be checked and retired on time, leave REF-TOR-DIFF out of the batch. Keep the same reviewed configuration throughout the batch. A replacement or extension requires a new snapshot review, requalification, and manifest decision before use. Treat stale or unavailable classification as an unavailable slot or a deviation under the protocol.

## Readiness evidence, traffic, and custody

Run the offline suites with nginx and OpenSSL on `PATH` from the repository root. They exercise synthetic header values, real loopback peers, a fabricated source cache, and no public host.

```sh
python3 reference-lab/test_lab.py -v
python3 reference-lab/test_conditions.py -v
```

For either candidate, give the readiness reviewer the exact HTTPS URLs and candidate catalog entry, expected status and task, TLS and delivery-path proof, approved client/tool versions, configuration revision, independent rule evidence and review date, operator authority and contact, interaction limits, and retirement date. Use a separately authorized qualification allowance. The proposed maximum per candidate is one ordinary scanner invocation (one Tor preflight, up to three Tor target requests, and up to one conditional direct request) and one load and one first-party navigation per browser when the branch permits it. Allow no qualification reloads. Account separately for any approved direct/fixture checks, including their exact route and request count, and for browser auxiliary requests such as favicon probes. REF-TOR-DIFF source acquisition proposes one index and one timestamped file retrieval, outside the measurement budget and subject to the same prior authorization. Follow the lower approved ceiling and stop if the expected evidence is unavailable inside it. Defer the condition when qualification or approval fails; do not repeat requests to obtain a particular result. [Readiness manifest requirements](../VALIDATION-REFERENCE-PACKET.md#future-live-readiness-manifest-fields)

For REF-TOR-DIFF, verify the frozen configuration and snapshot before eligibility traffic. The two families are covered by deterministic loopback tests. In an authorized IPv4 eligibility check, corroborate status and the configured decision for the scanner Tor and direct requests and each browser’s task actions, without recording the peer address. An approved transient diagnostic may retain only case/instrument and route IDs, UTC minute, supported family, branch (`listed`, `unlisted`, `unavailable`), and terminal status, tied to the frozen digest. If an effective membership decision cannot be corroborated within the approved procedure, defer. Retain no per-request diagnostic from unrelated traffic, no observed addresses or their hashes, no raw headers, no query parameters, and no request bodies.

Keep cached source bytes, generated includes, and restricted evidence outside the repository in owner-only storage excluded from sync and backup. Name the operator and specifically authorized reviewers in the approval. Keep nginx access logging disabled, preserve lifecycle-only diagnostics, and review network and platform logging before eligibility work. Remove the snapshot and generated config from the lab host when closing the batch. Delete local copies of raw qualification data and snapshot materials after audit, by the approved deadline and within 30 days of acquisition. Keep only the minimum reviewed provenance and categorical evidence on the approved structured retention schedule.
